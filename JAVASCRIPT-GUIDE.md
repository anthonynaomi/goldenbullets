# Golden Bullet — JavaScript Guide

This document explains every JavaScript file in this folder, what it does, and how it
fits into the Golden Bullet storefront. It is written so that a new developer can open
one file, read the matching section here, and understand the moving parts without
guessing.

Everything in this project is written with **zero npm dependencies**. The browser code
uses native ES modules and the browser APIs (`fetch`, `localStorage`, `IntersectionObserver`,
`BroadcastChannel`, `CustomEvent`). The tooling uses only Node's built-in modules
(`node:http`, `node:fs`, `node:child_process`, etc.).

---

## 1. The big picture

Golden Bullet is a **static storefront**: the HTML pages in `frontend/` are plain files
(generated by a build tool), and they all load a single ES-module entry point:

```html
<script type="module" src="js/main.js"></script>
```

`main.js` imports every other browser module and decides which page controller to run,
based on `<body data-page="…">`. There is no framework and no bundler — the browser loads
the module graph directly.

At runtime the pages talk to a small **mock API** served by `server.js` under `/api`.
If that API is unreachable, the catalogue falls back to the static file
`frontend/data/catalog.json`, so pages still render when opened from disk.

### Browser module graph (load order)

```
main.js                     (entry point — page controllers + boot)
 ├── api.js                 (bottom of the graph: fetch wrapper, config, money)
 ├── ui.js                  (shared UI primitives + initSharedChrome)
 ├── cart.js                (localStorage cart, drawer, badge, add-to-bag)
 ├── auth.js                 (JWT session + route guards)
 ├── validation.js          (field rules + form wiring)
 └── agegate.js             (18+ gate)
```

`api.js` imports nothing. Everything else may import `api.js`. `main.js` is the only
module the HTML files reference directly.

### Page → controller map

`main.js` reads `document.body.dataset.page` and calls the matching controller:

| `data-page` | HTML page | Controller in `main.js` |
|---|---|---|
| `home` | `index.html` | `initHome()` |
| `shop` | `shop.html` | `initShop()` |
| `product` | `product.html` | `initProduct()` |
| `cart` | `cart.html` | `initCartPage()` |
| `checkout` | `checkout.html` | `initCheckout()` |
| `login` | `login.html` | `initLogin()` |
| `register` | `register.html` | `initRegister()` |
| `account` | `account.html` | `initAccount()` |
| `blog` | `blog.html` | `initBlog()` |
| `blog-post` | `blog-post.html` | `initBlogPost()` |
| `contact` | `contact.html` | `initContact()` |
| `affiliate` | `affiliate.html` | `initAffiliate()` |
| `safety` | `safety-information.html` | `initSafetyReport()` |
| `faq`, `privacy`, `terms`, `refund`, `shipping`, `notfound` | policy / 404 pages | none — static only |

### Cross-cutting contracts

Because modules communicate without a framework, two contracts matter:

**Custom DOM events** (dispatched on `document`, listened for across modules):

| Event | Fired by | Meaning |
|---|---|---|
| `gb:age-confirmed` | `agegate.js` | Visitor confirmed 18+; cookie banner may show |
| `gb:cookie-show` | `agegate.js` | Ask the cookie banner to reveal itself |
| `gb:toast` | many modules | Show a toast; payload `{ message, variant, title }` |
| `gb:cart-changed` | `cart.js` | Cart contents changed (repaint badge/drawer/page) |
| `gb:cart-open` / `gb:cart-close` | `cart.js` / UI | Open or close the mini-bag drawer |
| `gb:auth-changed` | `auth.js` | Login/logout happened; header link re-renders |
| `gb:locale-changed` | `ui.js` | Country/currency changed; pages reload to re-price |

**`localStorage` keys** (all defined by `CONFIG` in `api.js` unless noted):

| Key | Owner | Purpose |
|---|---|---|
| `gb.token` / `gb.refresh` | `api.js`/`auth.js` | JWT access + refresh tokens |
| `gb.user` | `api.js`/`auth.js` | Cached profile (`firstName`, `email`, …) |
| `gb.currency` / `gb.country` | `api.js` | Selected currency / delivery country |
| `gb.cart` | `cart.js` | Cart items + applied discount |
| `gb.ageOk` | `agegate.js` | `"true"` once the visitor confirms 18+ |
| `gb.cookieOk` | `ui.js` | Cookie-consent choice and timestamp |
| `gb.announceClosed` | `ui.js` | `"closed"` once the promo bar is dismissed |
| `gb.promoEnd` | `main.js` | Rolling home-page countdown deadline |
| `freeShippingThreshold` | `cart.js` | Cached free-shipping threshold |

## 2. Browser modules

### 2.1 `frontend/js/api.js` — the foundation

**Role:** the single HTTP/config/currency layer. It is the bottom of the dependency graph
and imports nothing (`No imports: this module is the bottom of the dependency graph`).

**What it contains:**

- **`CONFIG`** — a frozen object built at load time. Reads the API base URL from a
  `<meta name="gb-api-base">` tag (falling back to `"api"`), a 12-second request timeout,
  and the `localStorage` key names listed above. It also points `staticFallback` at
  `data/catalog.json`.
- **`ApiError`** — a custom `Error` subclass carrying `status`, `code` and `details`.
  Convenience getters `isOffline` (status 0 = never reached the server), `isAuth`
  (401/403) and `isNotFound` (404) let callers branch on failure type.
- **`storage`** — a defensive wrapper around `localStorage` with `get/set/remove` and the
  JSON variants `getJSON/setJSON`. Every call is wrapped in `try/catch`, so the site does
  not crash in private-browsing modes where storage throws.
- **Token/user helpers** — `getToken`, `setToken`, `clearSession`, `getStoredUser`,
  `setStoredUser`.
- **`request(path, options)`** — the core `fetch` wrapper. It:
  - builds the absolute URL relative to `document.baseURI` and appends query params
    (skipping `undefined`, `null`, `""` and the sentinel `"all"`, and repeating keys for
    arrays such as multi-select filters);
  - optionally **de-duplicates** identical in-flight GETs (`dedupe`), so repeated calls
    (e.g. several components asking for the same product) share one network request;
  - enforces a **timeout** with `AbortController` and chains any caller-supplied `signal`;
  - attaches `Authorization: Bearer <token>` when `auth: true` and a token exists;
  - converts network/timeout failures into `ApiError` with friendly copy;
  - maps HTTP error statuses to human messages via `defaultMessageForStatus()`
    (400/401/403/404/409/422/429/5xx).
- **Static fallback** — `staticCatalogue()` fetches `data/catalog.json` once and caches it;
  `withFallback()` retries any *offline* catalogue call against that static file so the
  storefront still renders without the dev server. Single-record lookups also fall back
  (`lookupWithFallback()`): `api.products.get`/`api.blog.get` resolve by id or slug from
  that file, so Add to bag keeps working on a plain static host where the API answers 404 —
  not only when the browser is fully offline. **Reviews are deliberately excluded
  from the fallback** — reviews must come from the real API.
- **Currency + country layer** — `DEFAULT_CURRENCIES` (USD base plus USD/GBP/EUR/ZAR/KES/GHS
  with static demo rates), `DEFAULT_COUNTRIES`, runtime config injected from `/api/config`
  (`setRuntimeConfig`/`getRuntimeConfig`), and `getCurrencies`/`getCountries`.
  `getCurrencyCode()` resolves in priority order: stored currency → country's currency →
  configured default. `formatMoney(amountBase)` multiplies the store's USD price by the
  selected rate and formats it with `Intl.NumberFormat` (with a manual fallback).
- **`api` endpoint map** — the surface every page uses:
  `api.config`, `api.products.list/get/reviews/filters`, `api.blog.list/get`,
  `api.discounts.validate`, `api.newsletter.subscribe`, `api.contact.send`,
  `api.adverseReaction.send`, `api.affiliate.apply`, `api.orders.list/create/get` (auth),
  `api.auth.login/register/me`, and `api.account.update`.
- **`normalizeCollection(data, key)`** — tolerates several API shapes (`items`, named key,
  `results`, or a bare array) and returns a consistent `{ items, total, page, perPage, facets }`.
- **Small product helpers** — `productImage(product, index)` (with a default image),
  `discountPercent(product)` (compare-at vs price), and `isInStock(product)`.

**Why it matters:** every price shown anywhere, every network call, and every stored
credential flows through this file. It is also the file you change to point the
storefront at a real backend (the `<meta name="gb-api-base">` value).

### 2.2 `frontend/js/auth.js` — sessions and route guards

**Role:** JWT storage and session state on top of `api.js`.

**What it contains:**

- **JWT decoding** — `base64UrlDecode()` and `decodeJwt(token)` read the payload segment
  of a JWT. `isTokenExpired(token)` checks the `exp` claim against the clock.
  `isAuthenticated()` is "has a token **and** it is not expired".
- **`getDisplayName()`** — resolves a friendly name from the cached user
  (`firstName || name || email`).
- **Session mutations** — `login(email, password)` calls `api.auth.login`, stores the
  returned token/refresh token and user, then dispatches `gb:auth-changed`.
  `register(payload)` does the same for sign-up (and tolerates a response with no token).
  `logout({ redirect })` clears storage, dispatches `gb:auth-changed`, and optionally
  navigates away.
- **Route guards** — `currentUrl()` records where the user was; `requireAuth()` redirects
  anonymous visitors to `login.html?next=…` and returns the stored user when the session is
  valid; `redirectIfAuthenticated()` bounces signed-in users off the login/register pages;
  `safeNextUrl()` sanitises the `?next=` parameter so it can only ever be a **same-origin,
  non-protocol-relative** path (prevents open-redirect abuse).
- **`initAuthUI()`** — updates every header account link (`[data-account-link]`) to point at
  `account.html` or `login.html`, and swaps the label between `"Sign in"` and
  `"Hi, <FirstName>"`. It re-renders whenever `gb:auth-changed` fires.

### 2.3 `frontend/js/validation.js` — form rules and wiring

**Role:** a small, dependency-free form-validation toolkit used by every form on the site.

**What it contains:**

- **Primitive validators** — `isEmail`, `isPhone`, `yearsBetween`, and `isAtLeast18`
  (which also rejects future dates and dates before 1900).
- **Password strength** — `passwordScore(value)` returns `{ score (0–4), label, hints }`
  based on length, mixed case, digits, symbols, plus a small common-password blocklist and
  a repeated-character check. `initStrengthMeter(input, { meter, label })` wires it to a
  live strength bar and hint text.
- **`rules`** — a dictionary of composable rule factories: `required`, `email`, `phone`,
  `minLength`, `maxLength`, `adult`, `matches`, `accepted`, `password`, `pattern`. Each rule
  returns `null` when valid or an error message when not.
- **Field helpers** — `setFieldError`, `clearFieldError`, `validateControl` toggle the
  `.gb-field` `data-invalid`/`data-valid` state, set `aria-invalid`, and write the
  `.gb-field__error` message (an accessibility-minded contract used by the CSS).
- **`wireForm(form, schema, options)`** — the main entry point. It:
  - validates on `blur` or `input` (configurable);
  - re-validates all fields on submit, focusing and scrolling to the first invalid field
    and showing a `[data-form-error]` summary;
  - only calls the async `onSubmit(formData, form)` once everything passes;
  - returns `{ validateAll, runField, reset, isValid }` for programmatic control.
- **`formToObject(formData)`** — converts a `FormData` into a plain object, collecting
  repeated keys into arrays.

### 2.4 `frontend/js/cart.js` — the shopping bag

**Role:** a `localStorage`-backed cart with cross-tab synchronisation, discount codes,
shipping maths, and all the bag UI (drawer, badge, add-to-cart buttons).

**What it contains:**

- **Cross-tab sync** — a `BroadcastChannel("gb-cart")` (when supported) plus a `storage`
  event listener keep multiple open tabs in sync. Any mutation calls `emit()`, which
  broadcasts, notifies in-memory subscribers, and dispatches `gb:cart-changed`.
- **State** — `sanitizeItem()` hardens every stored line (valid id, clamped quantity up to
  `MAX_QTY = 20`, coerced price, normalised image/variant/prescription flags). `getCart()`
  always returns `{ items, discount }`, even if storage is corrupt. `write()` persists and
  emits; `subscribe(fn)` registers in-memory listeners.
- **Mutations** — `addItem(product, qty, { variant, openDrawer })` (merges same id+variant),
  `updateQty`, `removeItem` (drops the discount when the cart empties), `clearCart`,
  `setDiscount`, `getCount`.
- **`getTotals({ shippingMethod, country })`** — the pricing engine: subtotal, percent/fixed
  discount, free-shipping threshold (default ₦150,000), standard shipping ₦3,500 (free above
  the threshold), express ₦6,500, pickup free, plus international surcharges for non-NG
  destinations. Returns `{ items, discount, subtotal, discountAmount, shipping, total, count, … }`.
- **`applyDiscountCode(code)`** — validates a code through `api.discounts.validate` and
  stores the resulting discount on the cart.
- **Rendering** — `escapeHtml()` (local copy) and `renderCartItem(item)`, which returns the
  markup for one line (thumbnail, title link, variant, prescription note, quantity stepper,
  remove button, line price). This template is reused by the drawer, the cart page and the
  header.
- **`initCartDrawer()`** — the slide-in mini-bag: opens/closes on `gb:cart-open`/`gb:cart-close`
  or `[data-cart-open]`, locks body scroll, traps focus, restores focus on close, and
  delegates quantity/remove clicks.
- **`initCartBadge()`** — keeps every `[data-cart-count]` badge in sync and plays a short
  "bump" animation when the count increases.
- **`initAddToCartButtons()`** — one delegated `click` handler for all `[data-add-to-cart]`
  buttons. It fetches the product from the API, adds the selected quantity, shows a spinner,
  and fires success/error toasts.

### 2.5 `frontend/js/ui.js` — shared UI primitives

**Role:** the largest "library" module — small helpers, reusable widgets, HTML templates,
and one `initSharedChrome()` that boots all shared page furniture.

**Helpers:** `qs`/`qsa` (scoped query helpers), `escapeHtml`, `debounce`, `formatDate`
(`Intl` with fallback), `prefersReducedMotion`, `pageName`, and `setBusy(button, …)` which
swaps a button's content for a spinner and back.

**Widgets / initialisers:**

- `toast()` + `initToasts()` — a toast factory plus the `gb:toast` listener.
- `initAnnouncement()` — dismissible promo bar, remembered in `gb.announceClosed`.
- `initMobileMenu()` — off-canvas nav with scrim, scroll lock and a focus trap.
- `initHeaderSearch()` — turns header search forms into `shop.html?q=<term>` navigation and
  toggles the search panel.
- `initLocaleSelectors()` — populates country/currency `<select>`s from `api.js`, persists
  choices, updates "delivery to <country>" text, and dispatches `gb:locale-changed`.
- `initAccordions()` — accessible accordions (single- or multi-open) with correct
  `aria-expanded`/`aria-controls` and generated ids.
- `initTabs()` — accessible tablists with arrow/Home/End keyboard support.
- `initReveal()` + `initLazyImages()` — `IntersectionObserver` scroll-reveal animations and
  `data-src` image lazy-loading, both with reduced-motion / no-observer fallbacks.
- `initCountdowns()` — ticking day/hour/minute/second countdowns from `data-countdown`,
  paused when the tab is hidden.
- `initQtySteppers()` — plus/minus quantity controls, clamped to the input's min/max.
- `initCookieBanner()` — consent banner that waits for the age gate, remembers the choice in
  `gb.cookieOk`, and answers `gb:cookie-show`.
- `initCarousel()` — a responsive, keyboard-navigable, dot-paginated carousel.
- `openModal(modal)` — generic modal open/close with Escape handling and scroll lock.

**Templates:** `starsTemplate()` (star rating SVG), `productCardTemplate()` (a full product
card with badges, price, compare-at and add-to-bag button), `productGridSkeleton()`
(loading placeholders), `stateTemplate()` (empty/error/search states), and
`renderProductGrid(container, products)` (renders a grid or an empty state).

**`initNewsletterForms()`** — validates the email client-side and posts it via
`api.newsletter.subscribe`.

**`initSharedChrome()`** — the single call `main.js` makes to boot toasts, the announcement,
mobile menu, header search, locale selectors, accordions, quantity steppers, cookie banner,
newsletter forms, scroll reveal, lazy images, countdowns, and the footer year.

### 2.6 `frontend/js/agegate.js` — the 18+ gate

**Role:** blocks the store behind an age-confirmation modal until the visitor confirms they
are 18+.

**What it does:** `initAgeGate()` looks for `#gb-age-gate`. If `gb.ageOk` is stored, it hides
the gate immediately. Otherwise it:

- shows the gate, sets `data-gb-age-locked` on `<html>` and `.gb-no-scroll` on `<body>`,
  and marks the page behind it `inert` (no clicks, no tab stops, no scrolling);
- traps Tab focus inside the dialog, blocks Escape, and autofocuses the confirm button;
- on **confirm**: optionally remembers the choice, removes the lock/inert state, fires
  `gb:age-confirmed`, and asks the cookie banner to appear;
- on **exit**: shows an exit panel and navigates away (`location.replace`).

It exports `hasConfirmedAge()`, `clearAgeConfirmation()`, plus `MIN_AGE` (18) and `AGE_KEY`.

### 2.7 `frontend/js/main.js` — the entry point and page controllers

**Role:** imports every module, holds the per-page logic, and boots the site. It is the only
script the HTML pages load.

**Shared helpers at the top:** `params()` (URL query parsing), `setQuery(updates)` (syncs
filter/sort/page state into the URL via `history.replaceState`/`pushState`), and
`reportError(container, error, retry)` (renders a friendly error state with a "Try again"
button).

**Page controllers:**

- **`initHome()`** — a rolling 14-day countdown (`gb.promoEnd`), the featured-product grid,
  the latest blog posts, the reviews carousel, and the promo-code form.
  - `initReviewsCarousel()` / `reviewTemplate()` render verified reviews **only** if the API
    returns real ones; otherwise the section is hidden (the store never invents testimonials).
  - `postCardTemplate()` renders blog cards.
- **`initShop()`** — the catalogue browser. It seeds state from the URL (`q`, `sort`, `page`,
  `perPage`, `pack`, `availability`, `maxPrice`), fetches up to 100 products, then does
  client-side search / pack / stock / max-price filtering and sorting, pagination, active
  filter chips, and a facet sidebar (`deriveFacets()` when the API provides none). Every
  interaction writes back to the URL so the state is shareable and reload-safe.
- **`initProduct()` + `renderProduct()`** — loads the product named by `?id`, renders the
  gallery with clickable thumbnails, the buy box (price, compare-at, stock, quantity
  stepper, add-to-bag, prescription notice), label "facts" (batch, expiry, registration
  number, net content) and an information tab set. Supporting builders are `fact()`,
  `descriptionHtml()`, `listHtml()`, `directionsHtml()` and `warningsHtml()`, which carry the
  regulatory/safety copy and bracketed placeholders for label data.
  - `initProductReviews()` renders the average rating and verified review list, hiding the
    section when there are none; `initRelated()` shows up to three other products.
- **`initCartPage()`** — renders the full cart page, its order summary, the discount-code
  form, and quantity/remove interactions; re-renders on `gb:cart-changed` and
  `gb:locale-changed`.
- **`initCheckout()`** — shows the order summary and live totals, reveals the prescription
  upload field only when a cart line requires a prescription (disabled otherwise so it is
  never submitted), validates the full address/consent schema, then submits
  `api.orders.create`, clears the cart and redirects to `account.html?placed=<reference>`.
- **`initLogin()` / `initRegister()`** — password show/hide toggles, the registration
  strength meter, validation schemas (including the 18+ date-of-birth rule and password
  confirmation), and success redirects via `safeNextUrl()`.
- **`initAccount()`** — guarded by `requireAuth()`; shows the "order received" banner,
  fills and saves the profile form, wires logout buttons, and loads the order-history table.
- **`initBlog()` / `initBlogPost()` / `renderBlocks()`** — render the article index and a
  single article, turning a structured block array (`h2`, `h3`, `quote`, `list`, `ordered`,
  paragraphs) into safe HTML.
- **`initContact()`, `initAffiliate()`, `initSafetyReport()`** — validated forms that submit
  to `api.contact.send`, `api.affiliate.apply` and `api.adverseReaction.send` respectively,
  each with success/error status messaging.

**`boot()`** — runs on `DOMContentLoaded` (or immediately if already loaded). It initialises
the age gate, shared chrome, the cart drawer/badge/add-to-buttons and the auth UI; kicks off
`api.config()` (currency/country table); reloads the page on `gb:locale-changed` (except on
checkout, where form state is preserved); then dispatches to the right page controller inside
a `try/catch` so a single failing page never takes down the shell. Finally it adds the
`gb-ready` class that the CSS uses to reveal the styled page.

## 3. Development server

### 3.1 `server.js` — local dev server + mock API

**Role:** a dependency-free Node HTTP server that (a) serves `frontend/` as static files and
(b) exposes a mock JSON API under `/api`, so the storefront can be built and reviewed without
a real backend. Its header explicitly warns that it is **development-only**: secrets, users
and orders live in memory and reset on every restart.

**Configuration:** `PORT` (default `4173`), `HOST` (default `127.0.0.1`), and
`GB_DEV_JWT_SECRET` (default `golden-bullet-dev-secret`). The catalogue is read once from
`frontend/data/catalog.json`.

**Infrastructure:**

- A `MIME` map for the file types the site serves.
- `sendJson` / `sendError` / `readJsonBody` (JSON responses and a 1 MB request-body limit).
- A tiny **HS256 JWT** implementation (`signToken`, `verifyToken`, `bearer`, `requireUser`)
  used to protect order and account endpoints.
- Validation helpers `isEmail`, `isAdult` (18+, UTC-safe), and `reference(prefix)` which
  mints human-readable ids like `GB-…`, `ORD-…`, `USR-…`, `MSG-…`, `SAE-…`, `AFF-…`.

**Catalogue queries:** `listProducts()` (search, featured filter, sort, paginate),
`buildFacets()` (pack sizes + price range) and `findProduct()` (match by id or slug).

**API routes handled by `handleApi()`:**

| Method + path | What it does |
|---|---|
| `GET /api/health` | Returns `{ status: "ok", mode: "development-mock" }` |
| `GET /api/config` | Store config (currency table, discount codes, socials, payments, …) |
| `GET /api/products` | Product list with search/sort/pagination + facets |
| `GET /api/products/filters` | Facets plus an empty `collections` array |
| `GET /api/products/:id` | One product (by id or slug) |
| `GET /api/products/:id/reviews` | **Always returns an empty list on purpose** — the site only shows verified reviews and hides the section when there are none |
| `GET /api/blog` / `GET /api/blog/:slug` | Article index (sorted newest-first) and single article |
| `POST /api/discounts/validate` | Validates a code against `config.discountCodes` (with a minimum-subtotal rule for `FREESHIP`) |
| `POST /api/newsletter` | Email subscribe (dedupes, reports `alreadySubscribed`) |
| `POST /api/contact` | Contact message; stores it and returns a `MSG-…` reference |
| `POST /api/adverse-reactions` | Safety/adverse-reaction report; returns an `SAE-…` reference |
| `POST /api/affiliates` | Affiliate application; returns an `AFF-…` reference |
| `POST /api/auth/register` | Creates a user (validates name/email/18+/password length, rejects duplicate emails), returns a token |
| `POST /api/auth/login` | Checks the salted SHA-256 hash, returns a token |
| `GET /api/auth/me` | Current user from the bearer token |
| `PATCH /api/account` | Updates name/phone/email for the signed-in user |
| `GET /api/orders` | The signed-in user's order list |
| `POST /api/orders` | Rebuilds the cart server-side, applies the discount and shipping rules, stores and returns the order + reference |
| `GET /api/orders/:id` | One of the signed-in user's orders |

**Static serving:** `resolveStaticPath()` decodes the URL and **guards against path
traversal** (targets must stay inside `frontend/`). `serveStatic()` appends `index.html`
to directory-style paths, falls back to `<name>.html` for extension-less paths, sends the
custom `404.html` for misses, sets `X-Content-Type-Options: nosniff`, and caches HTML as
`no-store` while caching assets for an hour. The top-level server also sets
`Referrer-Policy` and `X-Frame-Options: SAMEORIGIN`. On startup it logs the storefront URL,
API URL, catalogue counts, default currency and a reminder that reviews are served empty.

## 4. Build and QA tooling (Node scripts, not shipped)

These live in `tools/` (plus `_probe.js` at the root). They are run manually with Node and
are not loaded by the website.

### 4.1 `tools/build-pages.mjs` — static page generator (~1,900 lines)

**Role:** generates **every** HTML page in `frontend/` from one shared shell, so the header,
footer, mobile menu, cart drawer, overlays, age gate and cookie banner are byte-for-byte
consistent across the storefront.

**What it contains:** a `SITE` config block (name, tagline, URL, support email/phone,
regulatory line, medical notice); an `icon` library of inline stroke-based SVGs (search,
user, bag, menu, close, chevron, truck, lock, support, leaf, flask, seed, shield, alert and
social icons); the `NAV` structure; `head()` (title/description/JSON-LD), `ORG_LD`,
`announcementMarkup()`, `localeMarkup()`, `headerMarkup()`, `mobileMenuMarkup()`,
`footerMarkup()`, `overlaysMarkup()` and `paymentBadge()`; layout helpers `layout()`,
`breadcrumbs()`, `pageHead()` and `noticeBlock()`; the long-form content builders
(`homeBody()`, `accordionMarkup()`, checkout country options, blog/FAQ/policy generators);
and `page(file, options)` registrations for all 19 pages (`index`, `shop`, `product`, `cart`,
`checkout`, `login`, `register`, `account`, `blog`, `blog-post`, `contact`, `affiliate`,
`faq`, `safety-information`, `privacy-policy`, `terms`, `refund-policy`, `shipping-policy`,
`404`).

**Use it** after changing shared chrome or page copy:

```bash
node tools/build-pages.mjs
```

It `mkdirSync`/`writeFileSync`s each file into `frontend/` and logs every page it wrote.

**Catalogue snapshot.** The generator also reads `frontend/data/catalog.json` at build time and bakes the product cards straight into the HTML, so the shipped pages match the rendered storefront without needing JavaScript or the API: `index.html` carries the `#featured-products` and `#best-sellers` grids, and `shop.html` carries the default first page (six per page) inside `#product-grid` plus the results count. `frontend/js/main.js` keeps that markup — the `prerendered` flag in `initShop()` and the `grid.children.length` guards in `initHome()` — and only re-renders when the visitor changes a filter, sort, search, or page. The builder's `productCard()` mirrors `productCardTemplate()` in `frontend/js/ui.js`, so keep the two in step, and rebuild after editing `data/catalog.json`.

### 4.2 `tools/check-pages.mjs` — headless page checker (~285 lines)

**Role:** automates QA by driving **headless Chrome over the DevTools Protocol** (no npm
dependencies) against a running dev server.

It captures uncaught exceptions, console errors, and failed network requests, then runs a
scripted sequence:

1. verifies a brand-new visitor is blocked by the age gate (main inert, focus trapped);
2. confirms age, then loads every page and runs structural assertions on it (product cards,
   facets, tabs, placeholder registration numbers, hidden reviews, forms, accordions, etc.);
3. exercises the **cart flow** (add to bag → badge, drawer, storage);
4. checks the cart page renders the stored line;
5. checks checkout with an item in the bag (summary, totals, prescription field, consents);
6. tests shop **search + reset**;
7. applies a **discount code** on the cart.

It prints `ok`/`FAIL` per step and exits non-zero if anything reported a problem.

```bash
node tools/check-pages.mjs http://127.0.0.1:4173
```

### 4.3 `tools/shots.mjs` — screenshot capture (~99 lines)

**Role:** captures full-page screenshots of every page by scrolling a headless Chrome
viewport and saving one PNG per slice into `_shots/<name>-<index>.png` (`-m` suffix with
`--mobile`). It seeds `localStorage` first to bypass the age gate, cookie banner and promo
bar, and works from a base URL argument (default `http://127.0.0.1:4173`).

```bash
node tools/shots.mjs http://127.0.0.1:4173 _shots --mobile
```

### 4.4 `tools/probe.mjs` — evaluate an expression on a page

**Role:** loads a page in headless Chrome and evaluates a JavaScript expression, printing
the JSON result. The expression is read from a file (default `_probe.js`), and the target is
configured with environment variables:

- `GB_BASE` (default `http://127.0.0.1:4174`)
- `GB_PAGE` (default `/index.html`)
- `GB_EXPR` (default `_probe.js`)

```bash
node tools/probe.mjs
```

### 4.5 `tools/dbg.mjs`, `tools/dbg2.mjs`, `tools/dbg3.mjs` — CDP connectivity debuggers

**Role:** low-level troubleshooting scripts for the headless-Chrome connection itself
(used when a tool above cannot attach). `dbg.mjs` opens a WebSocket to the DevTools endpoint
and logs handshake/version/target messages; `dbg2.mjs` and `dbg3.mjs` perform **raw TCP
WebSocket handshakes** (including Origin-header experiments and manual frame parsing) to
diagnose rejection or framing problems. They listen on ports `9335`, `9336` and `9337`
respectively, and each kills its Chrome instance and exits when done. They are diagnostic
helpers, not part of any build.

### 4.6 `_probe.js` — the default probe payload

**Role:** the expression `tools/probe.mjs` evaluates by default. It returns a snapshot of
computed styles and geometry for the header country/currency selects, the hero and promo
"outline" buttons, and the footer country select — a quick way to inspect what CSS is
actually applied to those controls on a live page.

## 5. Quick reference — "what do I edit for…"

| I want to change… | Edit… |
|---|---|
| A price, product, article or discount code | `frontend/data/catalog.json` |
| How API calls, prices or the API base URL work | `frontend/js/api.js` |
| Login/session behaviour or a protected page | `frontend/js/auth.js` |
| A form's validation rules or password meter | `frontend/js/validation.js` |
| Cart rules, shipping costs or the mini-bag drawer | `frontend/js/cart.js` |
| Header, footer, search, accordions, tabs, toasts, carousels | `frontend/js/ui.js` |
| The 18+ gate | `frontend/js/agegate.js` |
| What a page does after it loads | the matching controller in `frontend/js/main.js` |
| Mock API responses or static file serving | `server.js` |
| Shared HTML chrome or page copy | `tools/build-pages.mjs` (then re-run it) |
| Automated page/flow testing | `tools/check-pages.mjs` |
